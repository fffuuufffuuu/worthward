# 洞察容量提醒设计

## 目标

在洞察页的“正在 Focus”和“正在 Engage”容量卡片上，区分低于上限、恰好达到上限和超过上限三种状态，让用户及时看见注意力容量风险，同时保持所向安静、克制的视觉语言。

## 范围

- 只修改洞察页容量卡片的状态呈现。
- Focus 与 Engage 分别使用各自的当前数量和设置上限判断。
- 不修改容量上限、晋级、拖动、任性加入、每周梳理或数据保存逻辑。
- 不改变 Radar 和 Outcome 指标卡片。

## 状态规则

| 条件 | 视觉与文字 |
| --- | --- |
| 当前数量小于上限 | 保持现有中性卡片，不显示状态文字 |
| 当前数量等于上限 | 浅琥珀背景与边框，显示“已达上限” |
| 当前数量大于上限 | 浅珊瑚红背景与边框，显示“超出 N 项” |

状态不能只靠颜色表达；“已达上限”和“超出 N 项”必须作为可读取文字出现在卡片中。提醒不使用闪烁、脉冲或自动动画。

## 实现边界

- 在洞察指标渲染处计算 `normal`、`full`、`over` 三种状态。
- 复用每周梳理中已有的琥珀色“已满”和珊瑚红“超限”语义，但为洞察指标卡片使用独立、局部的样式类。
- 桌面和手机端使用相同判断；现有两列手机布局不变。
- 状态文字与背景、边框保持足够对比度。

## 验收

- Focus 与 Engage 低于上限时均无提醒。
- 任一指标恰好等于上限时，只在对应卡片显示“已达上限”和琥珀色状态。
- 任一指标超过上限时，只在对应卡片显示准确的“超出 N 项”和珊瑚红状态。
- 现有完整测试、类型检查和生产构建继续通过。
- 浏览器检查确认桌面与手机端状态清晰、布局无溢出。
