# 所向：洞察主题下钻与一键启动设计

日期：2026-08-22

## 目标

让洞察页的结构更符合阅读顺序，并让主题统计从“只能看”变成“可以追到具体卡片”；同时把日常启动从两步简化为双击一次。

## 洞察页布局

桌面端保持两列网格：

```text
第一行：Balance                         | STAGES / NOW
第二行：近 30 天关注最多的领域          | TOPICS / NOW
第三行及以后：现有停滞项目与其他指标
```

- Balance 与 STAGES / NOW 同行，Balance 占较宽区域。
- “近 30 天关注最多的领域”从 Balance 中拆出，成为独立卡片，放在 TOPICS / NOW 左侧。
- 删除漏斗图下方“宽度与当前数量对应，数字表示各阶段卡片数。”说明。
- 移动端按同一阅读顺序纵向排列：Balance → STAGES / NOW → 近 30 天 → TOPICS / NOW。

## 主题下钻浮窗

以下入口共用同一个主题浮窗：

- “近 30 天关注最多的领域”列表项；
- TOPICS / NOW 环形图扇区；
- TOPICS / NOW 图例项。

浮窗标题显示所选主题，内容按“探索 / 创造”分栏。每张结果卡显示：

- 标题；
- 当前阶段；
- 类别标签；
- 主题标签。

统计口径保持原样：

- 从 TOPICS / NOW 打开时，列出当前仍在用且包含该主题的卡片；
- 从近 30 天榜单打开时，列出促成该榜单统计的近 30 天新增或向前推进卡片；
- 近期已完成归档的卡片仍显示，并标注“已归档”，确保弹窗内容与榜单数字一致。

点击结果卡后的行为：

- 在用探索卡：关闭浮窗，进入探索板块，打开右侧卡片详情；
- 在用创造卡：关闭浮窗，进入创造板块，打开右侧卡片详情；
- 已归档卡：关闭浮窗，进入归档页，打开右侧卡片详情。

浮窗支持点击关闭按钮、遮罩及 Escape 关闭；键盘焦点清晰可见。没有匹配卡片的分栏显示明确空态。

## 聚焦名言

“注意力洞察”标题右侧显示一条聚焦、选择或注意力主题的名言和作者名。

- 使用本地内置、经过来源核实的候选集，不在打开页面时联网；
- 每次从其他板块进入洞察页时随机选择一条；
- 停留在洞察页期间保持不变，避免界面跳动；
- 移动端放在标题下方，不挤压“开始本周回顾”按钮。

## 滴答清单默认值

- 新工作区默认清单名改为“收集箱”。
- 个人种子数据同步改为“收集箱”。
- 加载已有数据时，仅当值仍为旧系统默认“Attention Workbench”时自动迁移为“收集箱”。
- 用户手动设置过的其他清单名不覆盖。

## 类别标签管理

设置页增加“类别标签”区域，探索与创造分开管理。每个类别包含名称和颜色。

- 添加：输入名称后创建，新类别自动获得一个与现有类别容易区分的颜色。
- 修改名称：同步更新该板块内所有使用旧名称的卡片，不能与同板块现有名称重复。
- 修改颜色：卡片色带、筛选按钮和洞察页中的类别标识立即使用新颜色。
- 删除：先显示受影响卡片数量；若仍有卡片使用，必须选择“迁移到同板块另一个类别”或“改为未分类”，不允许静默删除。
- 探索类别不能作为创造类别的迁移目标，反之亦然。
- 不增加类别排序功能；保持当前顺序和新增顺序，控制本轮范围。

类别定义保存到工作区设置中。现有固定类别在首次加载时迁移为可编辑定义；卡片仍以类别名称记录，重命名操作负责一次性同步更新，避免为本轮引入额外的类别 ID 体系。

## 数据保存与迁移

浏览器 `localStorage` 不再作为长期主数据源。主数据保存到当前 Windows 用户的本地应用数据目录，例如：

```text
%LOCALAPPDATA%\所向\workspace.json
```

原则：

- 本地服务只监听 `127.0.0.1`，不向局域网或互联网开放；
- 网页通过同源本地接口读取和保存工作区；
- 保存前验证数据结构，先写临时文件再替换正式文件，并保留最近一次可读备份；
- 保存失败时在界面明确提示，不把失败伪装成已保存；
- JSON 导入、导出继续保留，作为跨机器迁移和人工备份手段；
- 不保存滴答清单身份密钥，因为当前滴答集成仅唤起本机已登录客户端。

首次升级流程：

1. 在旧版本中导出一份 JSON 备份。
2. 新版本从本地数据文件读取；文件尚不存在时，尝试读取同一浏览器地址下的旧 `localStorage`。
3. 发现旧数据后先写入本地文件并读回验证，成功后才切换为文件存储。
4. 迁移失败时保留旧浏览器数据并提示使用 JSON 备份恢复，不清空原数据。

由于浏览器按端口隔离数据，迁移前必须确认旧版本实际使用的 localhost 端口，并让新版本首次在同一端口启动。

## 一键启动

采用“本地服务 + 桌面快捷方式”方案，不打包为独立桌面应用。

- 双击“所向”快捷方式后，先检查固定本地地址是否已可访问；
- 已运行时只打开浏览器，不重复启动；
- 未运行时在后台启动本地服务，由它提供网页并保存本地数据文件，等待地址可访问后自动打开浏览器；
- 固定使用同一个端口，避免浏览器按不同端口保存成两套本地数据；
- 启动脚本保存在项目内，桌面只放快捷方式，方便以后调整项目路径或启动逻辑。

具体固定端口在安装快捷方式前，根据用户现有数据所在的 localhost 地址确认，避免切换端口造成“数据看似消失”。

## 给其他人使用

不能直接分发当前开发文件夹，因为其中的个人种子文件包含从飞书和 Obsidian 导入的私人内容。后续生成的干净分发包必须：

- 不包含 `personal-seed.json` 和当前用户的本地数据文件；
- 首次打开为空工作台，只带默认类别与设置；
- 每个 Windows 用户的数据分别保存在自己的 `%LOCALAPPDATA%\所向` 目录；
- 滴答任务交给对方电脑上当前登录的滴答客户端创建；
- 若目标电脑没有运行环境，需另行制作包含便携运行环境的分发包，不能假设复制源码即可运行。

## 测试与验收

1. 洞察页桌面端与移动端顺序符合设计，漏斗说明消失。
2. 三种主题入口均能打开对应浮窗。
3. 近 30 天与当前主题使用各自口径，结果卡信息完整。
4. 点击探索、创造、归档卡分别进入正确板块并打开详情。
5. 名言每次重新进入洞察页重新抽取，单次停留不变化。
6. 新数据默认“收集箱”，旧默认值迁移，自定义值保留。
7. 设置页可分别管理探索与创造类别；重命名、改色和带迁移的删除结果正确。
8. 旧浏览器数据只在本地文件写入并读回成功后完成迁移；清理浏览器后数据仍可恢复。
9. 双击快捷方式可在未启动和已启动两种情况下正确打开同一地址。
10. 全部自动测试、构建和桌面/移动浏览器检查通过，浏览器控制台无错误。

## 范围边界

- 不改变近 30 天统计口径。
- 不增加投入时间记录。
- 不增加滴答清单后续同步。
- 不引入在线名言接口。
- 不打包 Electron、Tauri 或其他桌面壳。
- 本轮不制作面向其他人的完整安装包，只保证架构与数据文件边界支持后续制作干净分发包。
