# 「所向」软件说明网页改版设计

日期：2026-08-24  
状态：用户已确认内容结构、视觉方向与实施边界，等待书面设计复核

## 1. 目标与受众

页面面向第一次接触「所向」的其他用户。页面的首要任务不是罗列安装细节，而是让陌生用户理解：

- 为什么需要「所向」；
- 它如何帮助用户筛选值得投入的事项；
- 它与知识库、任务管理器的区别；
- 如何在三分钟内启动并开始使用。

网页随绿色版软件分发，必须可以完全离线阅读，不得包含开发者的真实卡片、API 密钥或其他个人信息。

## 2. 核心定位

首屏立论：

> 事情很多，真正值得投入的很少。

「所向」是个人注意力选择工具。它帮助用户在投入时间之前收拢线索、比较取舍，把有限注意力留给真正重要的探索与创造。

产品边界应明确表达：

- Obsidian 等知识库负责沉淀知识；
- 滴答清单等任务工具负责执行具体任务；
- 「所向」负责回答“什么值得我现在投入注意力”。

页面不得把「所向」描述成第二个知识库或待办清单。

## 3. 内容结构

### 3.1 固定导航

导航只保留四个入口：为什么、如何工作、软件特色、开始使用。右侧提供“打开所向”按钮。

### 3.2 首屏立论

首屏由产品名称、核心命题、简短解释和“开始认识所向”锚点组成。视觉右侧使用与 Logo 同源的收束环，表达注意力由外围线索向中心逐渐收拢。

### 3.3 工具边界

通过三种职责的并列关系说明：知识库保存知识，任务工具执行任务，「所向」帮助用户决定投入对象。该部分使用用户能够识别的行为语言，不解释接口、服务或数据结构。

### 3.4 注意力生命周期

展示 `Radar → Focus → Engage → Outcome & Review`，每个阶段必须同时提供中文解释：

- Radar：先收下可能值得关注的线索，不急于承诺；
- Focus：进入近期视野，与其他候选比较；
- Engage：正式承诺投入，并形成执行计划；
- Outcome & Review：留下成果、复盘经验并归档。

流程应呈现为逐步收束，而不是普通项目进度条。

### 3.5 软件如何帮助用户

使用无个人信息的示例界面展示以下能力：

- 探索与创造两个板块；
- Focus 与 Engage 在途数量提醒，防止同时投入过多；
- 注意力梳理，定期晋级、让位、停止关注和沉淀成果；
- AI 辅助主题标签、任务拆解和晋级建议，所有调用由用户主动触发；
- 将具体执行计划交给滴答清单，工作台不替代任务管理器；
- 洞察页面帮助识别阶段分布、主题分布和停滞事项；
- 工作区与 API 密钥保存在本机用户目录。

界面展示使用 HTML/CSS 构成的示例模型或仅含示例种子的截图，不使用现有个人工作区截图。

### 3.6 三分钟开始

启动说明按真实顺序呈现：

1. 将压缩包完整解压到一个文件夹，不要从压缩包内部直接运行；
2. 保持 `所向.exe`、`node`、`dist`、`server` 等内容在原有目录结构中；
3. 双击 `所向.exe`，等待浏览器自动打开本机工作台；
4. 记录第一条值得关注的线索；
5. 如需桌面入口，可为 `所向.exe` 创建快捷方式。

页面中的“打开所向”连接 `http://127.0.0.1:5174`。按钮附近要说明：如果工作台尚未启动，请先双击 `所向.exe`。

### 3.7 数据、隐私与常见问题

明确说明：

- 卡片数据位于 `%LOCALAPPDATA%\所向\workspace.json`；
- AI 密钥位于 `%LOCALAPPDATA%\所向\ai-credential.dpapi`，由当前 Windows 用户保护；
- 数据不会写入软件解压目录，移动或删除软件文件夹不会自动迁移或清除用户数据；
- 清理浏览器网站数据不会删除工作区主文件；
- 建议定期在设置中导出 JSON 备份；
- 分享软件时只分享干净绿色版压缩包，不分享 `%LOCALAPPDATA%\所向`。

常见问题只覆盖首次使用最可能遇到的问题：必须解压、端口被占用、浏览器未自动打开、快捷方式创建、数据备份与恢复。

## 4. 视觉系统

视觉概念为“注意力收束”。

### 4.1 颜色

- 深海蓝 `#173341`：主要文字、导航、按钮和稳定感；
- 雾白 `#F3F6F5`：页面底色；
- 矿物灰 `#C9D4D5`：分隔、边界和次要信息；
- 聚焦绿 `#50C5A7`：进入关注中心与积极行动；
- 行动珊瑚 `#E56B55`：创造板块、取舍提醒和必要警示。

不得增加无语义的渐变色或多套强调色。

### 4.2 字体

页面不得依赖在线字体：

- 展示标题：`Iowan Old Style`、`Baskerville`、`Songti SC`、`SimSun` 逐级回退；
- 中文正文：`Segoe UI`、`Microsoft YaHei UI`、`Microsoft YaHei` 逐级回退；
- 阶段、路径和数据：`Cascadia Mono`、`Consolas`、等宽字体逐级回退。

标题使用衬线字体表达判断与思考，正文保持适合长时间阅读的清晰度。

### 4.3 版式

桌面端采用宽阔留白和不对称首屏，正文最大宽度保持稳定。重要关系使用横向排布，说明文字不堆进小卡片。

移动端改为单列叙事，阶段流程允许纵向阅读；固定导航缩减为产品标识和“开始使用”，其余入口进入折叠菜单或自然滚动。

### 4.4 标志性元素与动效

唯一重点动效是“收束环”：首屏载入时，外围线索缓慢向中心收拢；滚动到生命周期时，环的四层含义对应四个阶段。

其他动效只用于导航状态、按钮反馈和内容进入视野，不使用持续漂浮、粒子背景或大面积视差。

当系统启用“减少动态效果”时，所有非必要动画必须停用。

### 4.5 反模板复核

不采用常见的暖米色杂志风、黑底荧光色或密集报纸排版。高级感来自准确的比例、留白、文字层级和单一标志性动效，而不是装饰数量。

## 5. 实施边界

本次改动范围：

- `guide/使用说明.html`：唯一内容源；
- `使用说明.html`：从唯一内容源同步的项目根目录副本；
- 绿色版目录中的 `使用说明.html`：通过打包流程生成；
- 新的绿色版压缩包：包含新版说明页。

本次不修改「所向」应用功能、工作区数据、用户密钥、种子数据或业务界面。

页面必须为单文件 HTML，不依赖网络、构建工具或额外说明页资源。CSS 和少量展示交互直接包含在文件内。

## 6. 可访问性与异常说明

- 所有导航与按钮可通过键盘访问，并显示清晰焦点；
- 正文与背景、按钮与背景满足清晰可读的对比度；
- 示例界面中的颜色不是唯一的信息表达方式；
- 移动端不得出现横向溢出；
- “打开所向”只负责打开固定本机地址，不声称能够自动启动未运行的软件；
- 对启动失败的说明要告诉用户下一步操作，不显示模糊错误。

## 7. 验收标准

### 7.1 内容

- 首屏能够独立说明项目意义；
- 明确解释它如何帮助用户及其与知识库、任务工具的边界；
- 包含真实的软件特色、启动步骤、数据位置、备份与常见问题；
- 不出现真实卡片、密钥或仅适用于开发者的内部信息。

### 7.2 页面

- 在桌面宽度与常见手机宽度下实际渲染检查；
- 导航、锚点、“打开所向”和常见问题交互可用；
- 关闭网络后仍能完整显示；
- 系统减少动态效果设置生效；
- HTML 无明显结构错误，浏览器控制台无页面脚本错误。

### 7.3 分发

- `guide/使用说明.html` 与根目录副本内容一致；
- 重新打包后，绿色版中的说明页与唯一源一致；
- 绿色版压缩包能够解压并通过 `所向.exe` 启动；
- 打包检查确认不包含个人卡片、API 密钥或个人迁移残留。

## 8. 实施顺序

1. 先完成语义化 HTML 和全部真实文案；
2. 实现视觉系统、示例界面与响应式布局；
3. 加入克制的收束环与必要交互；
4. 同步根目录副本并进行桌面、手机浏览器检查；
5. 重新打包并复核分发内容。
